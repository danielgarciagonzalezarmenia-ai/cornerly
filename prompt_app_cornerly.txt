6. FUENTE DE DATOS: SOFASCORE (SIN DATOS DE PRUEBA)
---------------------------------------------------------------------
IMPORTANTE - PASO 1 OBLIGATORIO: INVESTIGAR ANTES DE PROGRAMAR
Sofascore no publica una API oficial documentada; usa endpoints web
públicos/no oficiales. ANTES de escribir la lógica de la app debes:
 1. Investigar y descubrir los endpoints reales vigentes (por ejemplo
    revisando documentación comunitaria, repositorios en GitHub y haciendo
    peticiones reales de prueba para validar la estructura de respuesta).
    Referencia base conocida: https://api.sofascore.com/api/v1/ con rutas
    como:
      - Partidos programados por fecha de deporte:
        /sport/football/scheduled-events/{YYYY-MM-DD}
      - Cuotas de un partido: /event/{eventId}/odds/1/all
        (y variantes /odds/1/featured)
      - Estadísticas de un partido (incluye corners):
        /event/{eventId}/statistics
      - Detalle/resultado: /event/{eventId}
    VALIDA cada ruta con una llamada real; si alguna cambió, encuentra la
    vigente. No asumas, verifica.
 2. Documentar en un archivo docs/API_SOFASCORE.md los endpoints
    confirmados, parámetros, headers necesarios y un ejemplo REAL de la
    estructura de respuesta (sin inventar campos).
 3. Enviar cabeceras razonables (User-Agent de navegador móvil, Accept,
    Referer https://www.sofascore.com/) y respetar límites: máximo
    ~3-5 peticiones concurrentes, reintentos con backoff exponencial,
    caché local de lo ya consultado, pequeñas pausas entre peticiones
    para no ser bloqueado.
 4. Si hay bloqueo (403/429), mostrar mensaje claro al usuario y
    permitir reintentar más tarde; NUNCA rellenar con datos falsos.
 5. Aislar todo en una capa "SofascoreRepository" para poder cambiar la
    fuente fácilmente si Sofascore cambia sus rutas.
 6. Las cuotas pueden venir en formato fraccional (ej. "13/10"); conviértelas a
    DECIMAL: decimal = 1 + (numerador / denominador). Valida siempre el
    formato real que devuelva la API.

CLAVE: el mercado "Full time" / "1X2" da la cuota de Local (1), Empate (X)
y Visitante (2). El mercado de corners aparece en el apartado de cuotas
del partido como mercado de "Corners" / "Total corners" con líneas
(Más de / Menos de). Identifica por nombre del mercado y por la línea
exacta (7.5 y 11.5). Investiga cómo se llama exactamente en el JSON real.

7. LÓGICA DEL ANÁLISIS DIARIO (botón "Analizar partidos")
---------------------------------------------------------------------
Se ejecuta SOLO cuando el usuario toca "Analizar partidos", máximo UNA
vez por día (según la fecha local del dispositivo). El resultado se
guarda en base de datos local; al día siguiente el botón vuelve a estar
disponible.

ALGORITMO:
 1. Obtener todos los partidos de fútbol programados para HOY (zona
    horaria del dispositivo; el usuario está en Colombia, America/Bogota
    por defecto). Excluir partidos ya iniciados o terminados, cancelados
    o aplazados.
 2. Para cada partido, obtener las cuotas 1X2 (Local, Empate, Visitante).
    Si no tiene cuotas 1X2 -> descartar.
 3. Aplicar los DOS filtros (L = cuota del Local, V = cuota del
    Visitante):

    FILTRO A -> "MÁS DE 7.5 CORNERS"
      Condición: L < 1.38
      (La cuota del visitante NO importa.)
      Apuesta recomendada: Más de 7.5 corners.

    FILTRO B -> "MENOS DE 11.5 CORNERS"
      Condición: L > 2.05  Y  V > L  Y  V < 3.30
      (Es decir, el local no es tan favorito, el visitante es aún menos
      favorito que el local, y el visitante tiene cuota menor a 3.30.)
      Apuesta recomendada: Menos de 11.5 corners.

    Un partido solo puede caer en uno de los dos filtros (son
    excluyentes). Si no cumple ninguno -> descartar.
 4. Para los partidos que pasaron A o B, consultar el apartado de cuotas
    y buscar el mercado de corners:
      - Si NO existe el mercado de corners (o no existe la línea 7.5 en
        el caso A / la línea 11.5 en el caso B) -> DESCARTAR el partido
        (las casas de apuestas no ofrecen corners para ese partido).
      - Si existe -> guardar la cuota real de "Más de 7.5" (caso A) o
        "Menos de 11.5" (caso B).
 5. Ordenar la lista final por hora de inicio y guardarla en la base de
    datos con: id del evento, equipos, escudos, liga, hora, cuotas 1X2,
    filtro aplicado (A/B), selección (Más 7.5 / Menos 11.5), cuota de
    corners, fecha del análisis.
 6. Mostrar el progreso real durante el proceso y, al final, mostrar la
    lista completa en el dashboard, una tarjeta por partido, con scroll
    hacia abajo. Si ningún partido cumple, mostrar un estado vacío claro:
    "Hoy ningún partido cumple tus filtros".
 7. Poner los umbrales (1.38, 2.05, 3.30, 7.5, 11.5) como constantes en
    un único archivo de configuración fácil de modificar.

8. COMBINADAS, SALDO Y SEGUIMIENTO AUTOMÁTICO
---------------------------------------------------------------------
- El usuario selecciona N partidos (ej. 3) y define el monto. Cuota
  total = producto de las cuotas de corners elegidas. Ganancia potencial
  = monto x cuota total.
- Al confirmar: saldo disponible = saldo - monto. Se registra un
  movimiento en el libro de saldo (tipo "apuesta").
- SEGUIMIENTO: la app consulta periódicamente el resultado de los partidos
  pendientes:
    * Al abrir la app, siempre revisa todas las combinadas pendientes.
    * Además, usa tareas en segundo plano (paquete workmanager o
      background_fetch) para revisar cada ~15-30 min cuando iOS lo permita
      (reconoce que iOS limita las tareas en segundo plano; por eso la
      revisión al abrir la app es obligatoria).
    * Para cada partido finalizado, obtener los corners TOTALES reales
      (local + visitante) de /statistics y evaluar:
        - Selección "Más de 7.5": acierta si corners totales >= 8.
        - Selección "Menos de 11.5": acierta si corners totales <= 11.
- Una combinada es GANADA solo si TODAS sus selecciones aciertan;
  PERDIDA si al menos una falla (puede marcarse perdida apenas una falle,
  sin esperar a las demás). Si un partido se aplaza/cancela, esa
  selección se anula (cuota 1.00) y la combinada se recalcula.
- Al resolverse:
    * GANADA: saldo += monto x cuota total (se devuelve el monto más la
      ganancia). Registrar movimiento.
    * PERDIDA: el monto ya estaba descontado; solo se registra el
      resultado.
    * Enviar notificación local: "¡Combinada ganada! +$X" o "Combinada
      perdida", y mostrar la animación correspondiente al abrir la app.
- Historial completo guardado en local (nunca se borra salvo que el
  usuario lo pida).
